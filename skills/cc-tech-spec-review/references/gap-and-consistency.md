# 完备/盲区 + 自洽 + 金字塔归类 + 冗余/单源（引擎 G · C · T · D）

四件事都**只看文档自身和文档的引用**，不读项目代码"应该有"清单。

---

## 引擎 G 完备 / 内部盲区

**原则**：只揪文档**自己挖了一半的洞**，不强加"一份 X 文档必须有 Y 章"。判据是北极星——**这块新代码没指引，读者只能各自发挥**。

逐个"洞形态"扫：

### 开放枚举（列举没闭合）
- "支持 A、B **等**" / "诸如" / "包括但不限于" → "等"里还有啥？读者不知道边界。
- 状态机：列了状态没列全**转移**（某状态进得去出不来）。
- 列了**正常流程**没列**异常分支**（失败/为空/超限怎么走）。

**反例**：「消息类型支持文本、图片等」→ 视频？语音？卡片？新人写处理逻辑时不知道要不要覆盖。

### 悬空引用（引了却没定义）
- 引用了某术语 / 规则编号 / 模块 / 表，但文档**自己没定义也没指向哪**。
- "按 XX 策略处理"——XX 策略哪写的？

**反例**：「冲突时按乐观锁策略解决」——文档全篇没定义"乐观锁策略"具体怎么做（版本号？重试几次？失败如何）。

### 单边规则（有进无出）
- 定了"怎么创建"没定"怎么删除/撤销/回滚"。
- 定了"怎么加缓存"没定"怎么失效"。
- 定了"怎么进某状态"没定"怎么退出"。

### 前提无边界
- "X 情况下这样做"，但**没说非 X 怎么办**。
- 规则带隐含前提（"单机下…"），没说分布式/并发下还成不成立。

### 决策半截
- 给了方案没给**代价 / 适用边界**（详 decision-quality Qd3，完备视角是"这半截会让读者误用"）。
- 提了"后续优化"没说现在怎么办。

### 存量策略缺
- 新规上线，**存量代码怎么办**没说（一刀切会让存量全飘红，也没法落地）。

> ⚠️ 边界：不要写成"这份文档缺少性能章节/缺少安全章节"这种外部清单式 finding——那违反"只从文档自身推"。只报文档**自己起了头没收尾**的洞。真要补的大块缺失，作为"管辖范围内某块新代码无指引"在盲区清单里点一句，由作者决定要不要补。

## 引擎 C 自洽（内部矛盾）

文档跟自己打架。四种：

### 前后规则冲突
前文一条规则，后文另一条 / 一个示例与它相悖。
**反例**：§2「允许同名标签」/ §4「标签名唯一」。

### 示例违反自身规则（示例自打脸，常 P0）
正文立了规则 X，给的代码示例却违反 X。读者抄示例 = 抄了反例。
**反例**：§3.1「禁止字段注入，一律构造器注入」，§5.2 示例 `@Resource Bar bar;`（字段注入）。

### 同概念多名混用
同一个东西文档里叫好几个名（"会话/对话/session" 混用），读者以为是不同东西。（深度对齐走 [cc-terminology]）

### 默认值与校验冲突
默认值落在校验拒绝的区间；或两处给了不同默认值。

**复审特别提醒**：改写最容易在这里起新问题——局部补一条规则可能跟远处某条冲突。所以 C 在复审轮**全局重扫**，不只看改动处。

## 引擎 T 金字塔归类（规则/决策多时）

**目的**：一堆原子规则铺平没法读、找不到。按金字塔归成 MECE 类目，读者能快速定位"我这段新代码该守哪组规则"。

**注意**：这是给**原子规则归类**，不是 PRD 那种**整篇文档章节排序重排**。不动文档大章节顺序，只看规则有没有归好类。

### 先判：作者归类好不好（别对好文档强行重组）
T 的默认假设是"规则铺平无分组"，但很多文档作者**已经按主题分好节、每节有小结论先行**。先做这步判定：
- **已归类良好**（章节即主题、每组有引言小结论、MECE）→ 直接标 T✓，**复用作者的章节当金字塔树**呈现品质速览，**不二次聚类、不出重组 finding**。
- **仅当**铺平无分组 / 归错组 / 一条横跨两组 / 缺小结论 → 才进入下面"怎么聚类"+"查什么"，出 finding。

换句话说 T 在好文档上**就该安静**，复用作者结构即可，不是空引擎也不是硬找茬。

### 怎么聚类（类目从文档自身出）
- 类目按**规则主题**自然聚：从规则各自约束的对象/关注点归纳（命名 / 依赖与分层 / 事务边界 / 异常处理 / 测试归属 / 存量迁移 …）。
- 类目名用文档自己的词，不外部硬塞一套分类法。
- 顶层主题数控制在 ~7 个以内（多了说明还能再合）。

### 查什么（每条都可成 finding）
- [ ] **有没有归类**：几十条规则铺平、无任何分组 → 读者找不到（P1）。
- [ ] **MECE**：类目之间重叠吗（一条规则同时该进两组）？有遗漏的规则无处归吗？
- [ ] **归错组**：某条规则放错主题下，读者在相关主题里找不到它（可能 P0，致漏守）。
- [ ] **小结论先行**：每组首句是否一句话说清"本组管什么"？没有的话读者要逐条读完才知道这组关不关自己事。
- [ ] **ID 跟一级类目走**：id 前缀是否 = 金字塔一级类目、序号是否**类内递增不跨类目**？详下「ID 编号跟金字塔一级类目走」。

### ID 编号跟金字塔一级类目走（前缀 = 一级类目，类内递增）

规则 ID 必须**每个金字塔一级类目内部独立递增**：前缀用**类目**、序号**不跨类目**。

- ✅ `事务 → TX-01 TX-02` · `事件 → EVT-01 EVT-02`（前缀即一级类目，类内从 01 起）
- ❌ `MUST-01 MUST-02 MUST-03 MUST-04`（前缀用了**强制度**、且**跨类目全局流水**）
- ❌ `R1 … R50`（全局流水，无类目信息）

**两宗罪**：
1. **前缀用错轴**：拿强制度（MUST / SHOULD）当前缀 = 把会变的属性焊进 id —— 违反本 skill 自己「强制度做字段、绝不焊进 id」（编号约定）；强制度一升降，`MUST-03` 就得改名、全断引用。前缀该是**类目**（事务 / 事件 / 聚合 …），稳定不变。
2. **跨类目全局递增**：`01-50` 一根线穿到底，中间插一条 / 挪一类 → 后面全体重排 → 交叉引用全断（埋 D 冗余漂移源）。类内独立递增则插 `TX-09` 不动 EVT 段。

**收益**：前缀一眼定位类目（T 找得到）；类目前缀 + 类内递增 = 稳定引用（抗 D 漂移）；强制度退回 chip（呼应 Q 强制度分级）。

> 这条把「id 方案」和「金字塔归类」绑死：**id 前缀就是金字塔一级类目名**——归类对了，编号方案自然对。
> ⚠️ 只审**被审文档的永久规则 id**；本 skill 审查时给的临时标号（`R1 R2…` / `[F01]…`）是一次性标签，不受此约束。

### 报告呈现（金字塔树）
品质速览和 findings 都按这棵树组织：
```
【依赖与分层】— 本组管模块间怎么依赖、各层能调谁
  - R3 [MUST] ...
  - R4 [MUST] ...
【事务边界】— 本组管 @Transactional 用在哪层、边界怎么划
  - R7 [MUST] ...
```

**反例**：某分层规范 23 条 MUST 平铺无分组，"命名"相关的 3 条散在 #2/#11/#19 → 想查命名规则要全文搜。建议聚为【命名】组。

## 引擎 D 冗余 / 单源（DRY · single source of truth）

同一规则 / 定义 / 约束在文档里**重复出现多处**，没收口到单一权威源。只看文档自身。

**与 C 的分工（关键）**：C 抓**已经互相矛盾**的；D 抓**当前还一致、但物理上重抄多处、迟早漂移**的。**D = 防 C 于未发**。一段约束重抄 5 处、现在字字一致 → D（迟早有人改一处漏四处）；其中两处已经说法不一 → 升 C。

**与 C「同概念多名」的分工**：那条是同一东西取了**多个名字**（会话/对话/session）；D 是同一段**内容**物理重抄多份。一个是名漂，一个是体冗。

**与 T 的分工**：T 是「原子规则没归好类、找不到」；D 是「同一段内容物理重抄多份」。规则散落是归类问题（T），整段约束被复制粘贴是冗余问题（D）。

**危害（落北极星「写歧义 + 找不到」）**：改一处漏其余 → 漂移成矛盾；读者不知该信哪份 / 哪份最全。**D 永不单独 P0**——真出事是它漂成了矛盾，那时归 C。承载实质约束、各处独立维护的整段重复 = P1；短的导航性重提 = P2。

逐个"重复形态"扫：

### 规则正文复述
同一规则 ID 的完整约束在多处**重写**（不是引用，是重抄整段）。
**反例**：「DMS-01 性能例外」完整说明在 §0、DMS-02、APP-01、APP-03、API-01 等 ~12 处各写一遍。→ 留 DMS-01 一处全文，余处替换「见 DMS-01」。

### 多表同源
多张表定义**同一批角色 / 字段**，列大量重叠。
**反例**：§0 术语表 + §5 命名表 + APP-03 表都定义 AppService / Provider / TxService。→ 按轴拆分（概念表只留概念、命名表只留命名、行为表只留行为），互引，不重复列同一批行。

### 约束散点
同一约束散在多处各说一遍。

### 声明复述
同一声明性句子在多节重复。

### 冗余引用陈述（引用裹复述 —— 违职责单一）
规则的权威定义在**另一处**（本节/本文不是它的家），本处不止指向、还把被引规则的内容**复述一遍**。一句纯指针（「见 X-NN」/「按 §2」）是单源的**正确**用法；指针之外再抄一段内容 = 冗余副本，照样会漂移，且让本节背上本不属于它的规则（**违职责单一**——本节只该写本节负责的规则）。
**反例**：§4 校验规则正文又把 §2 已定义的「字段命名约定」整段重述，开头还写「如 §2 所述」——读者改 §2 时极易漏掉这段影子副本。
**修法**：删复述内容，只留纯指针「见 X-NN」；本节只留本节自己负责的规则。
> 与下「别误杀」的分界：判据是**这处指针带不带内容**。不带内容（只导航）= 健康，别报；带了内容（复述了被引规则在说什么）= 冗余引用陈述，照报。

### ⚠ 别误杀健康结构（D 最容易过度报）
- **纯指针交叉引用**（只写「见 X-NN」、不复述被引内容）是单源的**正确**用法——别报。但指针之外又**复述了被引规则的内容** → 冗余引用陈述（见上），照报：收口成纯指针。
- **总览 + 展开**（文首一句话总纲 + 正文详述）是有意的强调层次——别报；只报正文与正文之间互相重抄整段。
- 一条规则在两处分别讲**不同侧面**（一处讲 what、一处讲 how）不是重复——别报。

### 收口修法（报告里给，不只说"重复了"）
- **收口 + 引 ID**：留单一权威源，余处替换「见 X-NN」。
- **拆轴去重**：多表重叠按轴拆（概念/命名/行为各一表）——去列重叠，不是删表。
- **声明上提**：重复声明提到文首适用范围 / 专节。

> 修法允许「纯去重式合并」（收口、合表、上提），但**不动规则的逻辑归属与章节顺序**——那是 PRD 式整篇重排，不在本 skill（呼应 SKILL「不做的事」）。
