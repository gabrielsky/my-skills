# 改写模式

技术文档改写常见模式。**最小改动**，保留作者语气、术语、章节风格。目标始终是北极星：改完后新人照着能把新代码写对、写一致。

## 模式 1：不可判定 → 可判定（Q1）

| 原文 | 改写 |
|---|---|
| 方法不宜过长 | 单方法 ≤ 60 行，超出拆私有方法 |
| 应当适当解耦 | 跨模块只能调对方 `*Provider`，禁止注入对方内部 DAO/Service |
| 命名要清晰优雅 | 遵循命名表；禁拼音、单字母（循环计数器除外） |
| 保证高性能 | 关键链路 P95 < 2s |

## 模式 2：规则甩结论 → 补 WHY（Q2）

| 原文 | 改写 |
|---|---|
| 禁止 Service 直接 new 领域对象 | 禁止 Service 直接 `new` 领域对象——绕过工厂/聚合根会造出违反不变量的非法状态 |
| 查询必须走缓存 | 高频只读、容忍秒级陈旧的查询走缓存——降库压；强一致场景禁用 |

## 模式 3：只有正例 → 补反例（Q3）

**原文**：跨模块只能调对方 Provider + 一段正例。
**改写**：补 ❌ + 错在哪
```java
userProvider.findById(id);   // ✅ 走对方契约
@Resource UserDao userDao;   // ❌ 跨模块直接注对方 DAO
@Resource UserTxService svc; // ❌ 跨模块摸对方事务层
```

## 模式 4：决策甩结论 → ADR（Qd1-Qd3）

**原文**：缓存采用 Redis。
**改写**：
> **决策：会话缓存用 Redis**
> - 背景：会话上下文跨实例共享、读多写多、容忍过期。
> - 备选：本地 Caffeine（跨实例不共享，淘汰）。
> - 代价：网络往返 ~1ms，已纳入 P95 预算。

## 模式 5：反模式 → 最佳实践（E，最高价值）

把被写成钦定规范的反模式改成正确实践。**必带 WHY + 更优写法**。详 `tech-expertise.md`。

| 原文（被写成规范的反模式） | 改写 |
|---|---|
| 推荐字段注入 `@Resource` | 一律构造器注入——可测、依赖显式、循环依赖编译期暴露 |
| Service 内部方法标 `@Transactional` 互调 | 事务方法跨 bean 调用或自注入代理；同类 this 自调用事务不生效 |
| 实体只放 getter/setter，逻辑进 Service | 行为/不变量进领域对象（Bo），编排留 AppService——否则是事务脚本不是 DDD |
| 查不到就查库回填 | cache-aside + 空值缓存 + 互斥重建——否则热点失效瞬间击穿库 |
| 复合索引 (a,b,c)，高频按 b 查 | 按高频条件定索引列序；范围列放末位，否则最左前缀失效 |

## 模式 6：空话形容词 → 量化（arch Q）

| 原文 | 改写 |
|---|---|
| 高性能 | 关键链路 P95 < 2s |
| 高并发 | 峰值 500 msg/s |
| 高可用 | 月可用性 ≥ 99.9% |
| 实时同步 | 经 Kafka 异步，秒级最终一致 |

## 模式 7：开放枚举 → 闭合 / 显式兜底（G）

| 原文 | 改写 |
|---|---|
| 支持文本、图片等 | 支持文本、图片、语音、视频、卡片（共 5 类）；未列类型按"不支持"拒绝并记日志 |
| X 时这样处理 | X 时这样；非 X 时 {显式说明 / 标"本期不支持"} |

## 模式 8：规则铺平 → 金字塔归类（T）

几十条规则平铺 → 按主题聚成 MECE 组，每组加一句小结论先行：
```
【依赖与分层】— 本组管模块间依赖与各层调用边界
  - R3 [MUST] …
  - R4 [MUST] …
【事务边界】— 本组管 @Transactional 用在哪层
  - R7 [MUST] …
```
只重组**规则归类**，不动文档整体章节顺序。

## 模式 9：散点 → 表格

并列规则/决策超 3 项上表。
规则表：`| 编号 | 强制度 | 规则 | 正例/反例 |`
决策表：`| 编号 | 决策 | 备选 | 选它理由 | 代价 |`

## 模式 10：重复抄录 → 引用（防漂移）

把别处已有规则整段抄进来 → 将来两处不同步。改为：
> 命名规范见 `dev-docs/domain-layer-specification.md`，本文不重复。

只在本文档负责的边界内写权威内容，其余引用（呼应 C 多名混用、避免与既有 guidelines 冲突）。

## 模式 11：口语化 → 书面

| 原文 | 改写 |
|---|---|

| 这块儿逻辑 | 该模块逻辑 |
| 反正就是 | （删，直接给结论） |
