# cc-testing-boundaries

测试聚焦**有真实回归风险的业务规则与对外契约**。编写测试、规划测试点或执行代码审查时，**禁止**为以下场景单独编写测试用例（审查时也不得因缺少此类用例要求补测）：

1. **弱校验**：
   - 字符长度、集合数据条数、简单必填/非空/正数等基础参数检查（如 `@NotNull`、`@NotBlank`、`@Size`、`@Positive` 等声明式或简单卫语句校验）。
2. **类型转换**：
   - DTO / VO / Command / Domain / Entity 之间的字段映射、枚举/状态码简单映射、纯数据载体组装（其正确性通过业务行为测试间接覆盖；仅含独立复杂计算或解析算法的工具方法除外）。
3. **技术工具的使用**：
   - 分布式锁、乐观锁、悲观锁、Alertmanager 告警等技术组件/中间件的调用或注解接入本身，不单独写测试验证工具机制或告警触发。

> 若当前仓库存在项目级测试规范（如 `testing-guidelines`），在遵守上述不测边界的基础上，按项目规范执行测试分层、命名与断言。
