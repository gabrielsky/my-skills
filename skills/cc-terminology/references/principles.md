# 术语原则（详版）

SKILL.md 给了十条速记，这里展开「为什么」和「怎么判」，每条配本仓库 PRD 的真实例子。判术语好坏、写诊断报告时查这份。

---

## 1. 唯一性：一个概念一个词

同一个对象，全文只允许一个钦定词。**最常见、最隐蔽的术语病**：作者写着写着换了个词，自己没察觉，读者却以为是两个东西。

- 坏：同一拨人，一会儿"用户"、一会儿"客户"、一会儿"会员"。
- 判法：列出文中所有名词，问"这两个词指的是同一个东西吗？" 是 → 必须合并。
- 例（本仓库）：参与竞争应答的 Agent 钦定为「候选 Agent」，不再叫"参选 Agent""候选客服"。

## 2. 一致性：全文同一写法

唯一性的"动作版"——选定钦定词后，全文每一处都用它，包括简称。简称也要在表里钦定（`（简称焦点）`），不能这段叫"会话焦点"那段随手简称"焦点商品"又"主商品"。

- 判法：对每个钦定词，grep 全文看有没有漏网的旧写法。
- 例：「会话焦点」简称「焦点」，二者都是钦定词；不允许再冒出"主聊商品""锁定商品"。

## 3. 无歧义：一词只一义

一个词在文中只能有一个意思。泛词是重灾区——"状态""信息""数据""配置"单独用几乎必歧义。

- 判法：一个词出现多处，逐处问"这里具体指什么？" 答案不一致 → 加限定词拆开。
- 修法：泛词加业务前缀。"状态" → "订单状态" / "支付状态" / "候选状态"。
- 例：本仓库把笼统的"变量"拆成「环境变量」「预填变量」「后填变量」，各有明确所指。

## 4. 可定义：一句话能划清边界

每个术语都要能用一句话说清"是什么、不是什么"。**说不清，往往不是表达问题，是这个概念本身没想清楚**——这时别硬写定义糊弄，回去找作者澄清。

- 判法：试着给每个术语写一句话定义。写不出干脆的边界 → 标记为"概念待澄清"。
- 例：「句内提及」= 消息级、买家这句随手贴的商品、siren 从卡片解析、对接方不传。边界四个限定都清晰。

## 5. 区分性：相近概念用明显不同的词

相近但不同的概念，名字要拉开距离，别让读者靠上下文猜。**对立概念更进一步：名字刻意呼应**，成对概念用成对的词，读者看名字就懂关系。

- 坏：「取消」「关闭」「撤销」「作废」混用，分不清哪个是哪个动作。
- 判法：找出语义相邻的一组词，问"光看名字能区分吗？" 不能 → 改名。
- 例（呼应）：`会话焦点 ↔ 句内提及`（整通对话 vs 这一句）、`预填 ↔ 后填`（对接方填 vs siren 填）。对立面在名字上就照应上了。

## 6. 业务对齐：用业务方的真实说法

产品文档的术语应取自业务方/真实场景的叫法，别把工程实现的黑话塞进来当产品术语。反过来，文档术语又要能锚到代码（见原则 8），所以理想是"业务词为正名、代码标识作锚"。

- 坏：产品文档里管"优惠券"叫"promotion entity"。
- 判法：问"业务同学/客服平时怎么称呼这个？" 用那个词。

## 7. 显式优先：缩写、代号首次出现给定义

缩写、内部代号、英文简称，第一次出现时给全称或一句话定义，别假设读者都懂。

- 判法：扫所有大写缩写/英文词，首次出现处有没有解释。
- 例：本仓库 `LLM`/`SLM` 在术语表里点明"大模型/小模型"及各自用途，正文才放心用缩写。

## 8. 命名映射：文档术语 ↔ 代码字段 ↔ UI 文案 可追溯

这是术语表「代码标识」列存在的全部理由，也是技术文档最值钱的一条。一个中文术语必须能追到它在代码里叫什么、在界面上显示成什么。三者对不上是 P0 级问题——研发照文档去代码里找，找不到就理解错。

- 判法：每个术语，问"代码里它叫啥？" 答不出或与代码实际字段冲突 → 派子 agent 核实、记 finding。
- 例：「会话焦点」↔ `focus_item_info`/`focus_trade_info`；「句内提及」↔ `mentioned_item_infos`。中文呼应、代码字段也呼应。

## 9. 稳定性：术语定了别随意改

术语一旦钦定并散布全文，改名的成本是全局的。非改不可时（如发现撞名、业务改叫法），必须全局一次性改干净并记录，不能新旧并存。维护模式里**不擅自改既有表项**就是这条——改动留给用户拍板。

- 判法：发现一个"更好的名字"时，先评估改名波及多少处，值不值。

## 10. 粒度恰当：不过度细分，也不过度笼统

术语颗粒度要配得上读者的认知。拆太细——每个微小变体都起个名——增加记忆负担；笼统——一个词盖太多——生歧义（回到原则 3）。

- 判法：一个术语如果只在一处出现、且能用已有词+限定说清，可能不必单列；一个词如果盖了三种以上不同所指，该拆。
- 平衡点：能复用既有术语+限定词表达的，优先复用；确实是独立常用概念的，才单列。
