# PRD 结构模板（金字塔原则）

供 prd-review 输出"建议骨架"时使用。也可直接给 PM 当新 PRD 模板。

## 核心原则

1. **结论先行**：每章首段一句话说清"做什么 / 不做什么 / 范围边界"。读者读首段即可决定是否往下读。
2. **按重要程度排序**：先答 Why（需求概述），再答 What 业务，再答 What 表现（UI），最后答辅助层（运营治理 / 技术对接 / 验收）。颠倒顺序读者认知负担会爆炸。
3. **相关聚合，顶级少而精**：6 章为目标上限。
   - 操作日志 / 权限 / 统计埋点 同属"治理"，合为「四、运营与治理」三个子节。
   - 背景 / 目标 / 用户 / 用例 同属"需求是什么"，合为「一、需求概述」五个子节。
   - 顶级 > 8 章基本说明聚合不够，需要再合并。
4. **MECE**：同层章节不重叠、不遗漏。子章节是父章节的完备分解。
5. **业务 ↔ UI ↔ 治理 三分离**：
   - **业务规则章**只写"系统应该怎么算 / 怎么存 / 怎么转移"。不出现控件名。
   - **UI 章**只写"用户看到什么 / 点哪里 / 跳哪里"。业务校验只引用，不重复定义。
   - **运营与治理**（操作日志 / 权限 / 埋点）聚合为一章三子节，方便对应下游运维 / 安全 / 数据各取所需。
6. **可引用而非复制**：同一规则只在一处定义；其他章节引用「见 2.4」即可，避免改一处忘改另一处。

## 完整目录模板

序号规则：顶级 H2 用中文「一、二、三…」；子标题 H3/H4 用数字 `1.1`、`1.1.1`。

```
# {模块名} PRD

## 一、需求概述
### 1.1 业务背景与痛点
- 现状：……
- 痛点：……
- 数据支撑：（量化痛点）
### 1.2 目标与非目标
- 目标 1：……（可量化）
- 目标 2：……
- 非目标 / 本期不做：X、Y，原因 / v2 评估
### 1.3 成功指标
| 指标 | 口径 | 目标值 | 衡量周期 |
### 1.4 角色定义
- 角色 A：……
- 角色 B：……
### 1.5 核心用例
- 用例 1：作为 X，我希望 Y，以便 Z
- 用例 2：……
- 用例流程图 / Demo 链接

## 二、业务规则
### 2.1 术语表
| 术语 | 定义 | 别名（避免使用） |
### 2.2 业务字段（仅业务语义；类型 / 长度 / 存储 由研发实现，PRD 不写）
| 字段 | 业务含义 | 必填 | 默认值 | 枚举/取值范围 | 是否可改 | 改后行为 |

例外：若本 PRD 是「统一业务模型 / 开放平台 API / 跨系统对接」性质，则需补 类型 / 长度 / Nullable / 版本演化策略 列。
### 2.3 状态机
- 状态枚举：……
- 状态转移图：……
- 每个状态允许的动作矩阵
- 并发策略（锁 / 后写覆盖 / 冲突提示）
### 2.4 业务校验与计算
| 规则编号 | 触发条件 | 校验逻辑 | 失败行为 |
### 2.5 边界与异常
- 数量上限 / 容量 / 速率
- 空状态 / 依赖系统降级 / 越权拦截
- 数据迁移（存量映射）
### 2.6 与现有模块的依赖与复用边界
- 复用：……（指明范围）
- 不复用：……

## 三、UI 交互
### 3.1 入口与信息架构
- 一级入口：……
- 页面树
### 3.2 页面布局
- 列表页（线框 / Demo）
- 创建 / 编辑页
- 详情页
- 二次确认弹窗
### 3.3 控件清单
| 字段 | 控件类型 | placeholder | 默认值显示 | 校验依据（引用 2.4 规则编号） | 错误文案 |
### 3.4 交互流
- 操作路径
- 跳转与回跳
- 灰显 / 隐藏规则
### 3.5 各种态展示
- 空态 / 加载态 / 错误态 / 越权态

## 四、运营与治理
### 4.1 操作日志
- 记录的动作清单
  | 动作 | 触发条件 | 备注 |
- 日志字段
  | 字段 | 取值 | 备注 |
  | 操作人 | 当前登录用户 | 主/子账号区分 |
  | 操作时间 | 服务端时间戳 |  |
  | 终端 / IP |  |  |
  | 动作类型 | 枚举 |  |
  | 对象快照 | 名称/版本号 | 取动作发生时刻 |
  | 变更摘要 | 前后 diff | 仅记关键字段 |
- 不记录的动作及理由
- 展示位置与保留期
### 4.2 权限
- 角色权限矩阵
  | 资源 | 动作 | 主账号 | 子账号 | 客服 | 运营 |
- 跨租户 / 跨商户 隔离
- 越权拦截与文案
### 4.3 统计分析与埋点
- 业务指标定义
  | 指标 | 口径 | 维度 | 计算公式 | 衡量周期 |
- 埋点事件清单
  | 事件名 | 触发时机 | 字段 | 前端/后端 | 接入方 |
- 数据看板入口

## 五、技术对接
### 5.1 与 {算法 / 风控 / 第三方} 的同步
- 同步时机（草稿保存 / 发布 / 启停 / 删除）
- 协议（HTTP / MQ / 文件）
- 字段集合
### 5.2 入参 / 出参 / 错误码 / 兜底
- 入参 schema
- 出参 schema
- 错误码表
- 超时 / 重试 / 失败兜底
### 5.3 SLA 与容量

## 六、验收与上线
### 6.1 验收用例（每条可测试）
### 6.2 性能 / 容量 SLA
### 6.3 灰度与回滚方案
### 6.4 兼容性与数据迁移
```

**序号规则要点**：
- 顶级 H2 中文序号：`## 一、`、`## 二、` …
- 子标题 H3 数字：`### 1.1`、`### 1.2`
- 三级 H4 继续数字：`#### 1.1.1`
- 跨章引用：顶级中文（`见 四、运营与治理`），子级数字（`见 2.4`）
- 顶级目标 ≤ 6 章；超 8 章基本是聚合不够。常见可聚合：
  - 操作日志 / 权限 / 统计埋点 → 运营与治理
  - 背景 / 目标 / 用户 / 用例 → 需求概述
  - 跨团队接口契约 / SLA → 技术对接
  - 验收用例 / 灰度 / 数据迁移 → 验收与上线

## 章节归属判定规则（出现错位时往哪迁）

| 现象 / 关键词 | 应归属 |
|---|---|
| 「输入框 / textarea / 下拉框 / 单选 / 多选 / 按钮 / 弹窗 / placeholder / 错误文案」 | 三、3.x UI 交互 |
| 「必填 / 枚举 / 唯一性 / 业务校验规则」 | 2.4 业务校验（3.x 中只引用编号） |
| 「长度 X-Y / 字符类型 / 数据库存储」 | 不属 PRD（研发实现）；除非数据契约 PRD |
| 「状态 / 草稿 / 线上 / 已下线 / 启用 / 停用 / 转移」 | 2.3 状态机 |
| 「灰显 / 不可见 / 隐藏」 | 3.4 交互流（前提是 2.3 已定义状态对应可触发动作） |
| 「记录…日志」 | 4.1 操作日志 |
| 「谁能 / 主账号 / 子账号 / 权限」 | 4.2 权限 |
| 「数据 / 看板 / 核销率 / DAU / 埋点」 | 4.3 统计分析与埋点 |
| 「外部系统 / 风控侧 / 算法侧 / 同步 / 协议」 | 五、技术对接 |
| 「上线 / 灰度 / 回滚 / SLA / 数据迁移」 | 六、验收与上线 |
| 「数量上限 / 配额」 | 2.5 边界（提示文案 → 3.3） |
| 「与 XX 关系 / 复用 XX」 | 2.6 复用边界 |
| 「业务背景 / 痛点 / 目标 / 角色 / 用例」 | 一、需求概述（合 1.1-1.5） |

## 业务 vs UI 拆分示例

**反例**（业务/UI 混写 + 写了不该 PRD 写的字段长度）：
> 创建优惠券时，名称用单行输入框输入，长度 1-50 字，不能为空，错误提示"名称不能为空"，允许重名。

**改写**：
> 业务规则（2.2 字段 / 2.4 校验）：
> - 名称：必填、允许重名（不做唯一性校验），校验规则编号 R01。
> - （字段长度由研发实现决定，PRD 不约束；除非业务有明确限制如"短信 70 字"）
>
> UI 交互（3.3 控件清单）：
> | 字段 | 控件 | placeholder | 校验依据 | 错误文案 |
> | 名称 | 单行输入框 | 输入优惠券名称 | 见 2.4-R01 | 名称不能为空 |
