# 改写模式

PRD 表达优化的常见模式。改写时尽量**最小改动**，保留 PM 原意与语气。

## 模式 1：模糊量词 → 量化

| 原文 | 改写 |
|---|---|
| 数量不宜过多 | 单商户最多 20 张 |
| 性能要快 | P95 响应时间 < 500ms |
| 系统稳定即可 | 月度可用性 ≥ 99.9% |
| 简介不要太长 | 短信场景业务硬限 70 字（仅在业务有明确约束时量化；普通字段长度属研发实现，PRD 不写） |

## 模式 2：模糊主语 → 显化执行方

| 原文 | 改写 |
|---|---|
| 即时生效 | 用户点击保存后，后端事务提交即对线上版本生效（< 1s） |
| 自动应用 | 用户领取后，自动适用当前生效版本的优惠券规则 |
| 走草稿流程 | 修改进入草稿状态；发布按钮触发后写入线上版本表 |

## 模式 3：长句拆解 → 短句 / 表格

**原文**：
> 系统现有的"平台预置优惠券"能力保持不变（名称、适用范围、面额、有效期、发放数量、使用门槛、相关限制等），本次新增"自定义优惠券"能力，整体流程复用平台预置券（含草稿 / 测试 / 发布 / 状态机），仅在以下 6 点存在差异。

**改写**：
> 本次新增"自定义优惠券"。整体流程复用平台预置券，差异点见下表。
>
> - 复用范围：名称、适用范围、面额、有效期、发放数量、状态机、草稿 / 测试 / 发布。
> - 差异点：见下表 6 行。

## 模式 4：口语化 → 书面

| 原文 | 改写 |
|---|---|
| 咱们这边支持 | 系统支持 |
| 给大家看下流程 | 流程如下 |
| 我们的目的是 | 目标是 |
| 这块儿 | 该模块 |

## 模式 5：散点 → 表格

并列字段定义、并列规则、并列状态描述，超过 3 项就上表格。表格列固定：

业务字段表 5 列（仅业务语义；**不含类型/长度**，那是研发实现）：
| 字段 | 业务含义 | 必填 | 默认值 | 枚举/取值范围 |

> 例外：数据契约 PRD（统一业务模型 / 开放平台 API / 跨系统对接）才加 类型 / 长度 / Nullable / 版本演化 列。

规则表 4 列：
| 编号 | 触发条件 | 系统行为 | 备注 |

状态表 3 列：
| 状态 | 进入条件 | 退出条件 |

## 模式 6：隐含假设 → 显化

| 原文 | 改写 |
|---|---|
| 复用现有品类树 | 复用「品类树」模块（产品文档 X），仅引用其 id；不修改其数据模型 |
| 由风控决定 | 风控侧根据「适用范围」字段和下单上下文做核销校验；本 PRD 不规定风控实现 |
| 后期可调 | 上限值通过运营后台「商户配置 - 优惠券数量上限」可调；MVP 默认 20 |

## 模式 7：默认值与校验同列

任何字段定义，默认值与校验规则放一起，不要分开两段说。

**反例**：
> 备注默认为空。
> ...（隔了三段）...
> 备注是否必填、是否参与核销规则。

**改写**（一张表）：
> | 字段 | 默认值 | 必填 | 业务规则 | 错误文案 |
> |---|---|---|---|---|
> | 备注 | 空 | 否 | 不参与核销规则 | 必填校验时："备注不能为空" |

> 注：具体长度上限属研发实现，PRD 不写（除非业务硬约束如短信 70 字）。

## 模式 8：「待定」具象化

| 原文 | 改写 |
|---|---|
| 暂未支持 | 本期不支持；下版本（v2）评估 |
| 暂无 | 本期不做：原因 / 风险 / 何时补 |
| 待定 | 待 {人} 在 {时间前} 确认；阻塞 {下游环节} |

## 模式 9：错误文案模板

每个校验规则配错误文案。文案模板：

- 必填：「{字段名}不能为空」
- 长度：「{字段名}长度为 {min} 到 {max} 个字」
- 枚举：「{字段名}只能为 {枚举值}」
- 重复：「{字段名}已存在」（如果做唯一性）
- 越权：「无权操作」（不暴露具体资源）

## 模式 10：「复用 XX」标准句式

> 本字段 / 流程复用 {模块名}（详见 {文档链接 / 章节}）：
> - 复用：A、B、C
> - 不复用：D（本模块覆盖：…）
> - 边界条件：…

避免「复用现有优惠券模板」这种一句话留白。
