# design-proposal

出**代码设计方案**时用。核心约束一句话：**别为了迁就坏设计去改好代码——先用 5 Why 追到设计决策层，判定上游设计是否合理，合理才允许下游适配。**

**默认立场**：现有代码是**待评估对象**，不是约束条件。
"现有代码就是这么写的"不能作为方案的任何一条理由。

**与全局 CLAUDE.md 那条规则的分工**：CLAUDE.md 里是常驻的一句话版本，随时生效；本 skill 是**仅手动 `/cc-design-proposal`** 的展开版，强制走完四节 + 5 Why 取证，用在正式出方案、需求评估、重构方案、技术选型这类要留档的场景。

## 接受输入 / 触发

- **仅手动触发**。用户显式 `/cc-design-proposal [目标]` 或点名调用本 skill 才走。
- 目标可以是：一句需求描述 / issue 号 / 一段"这里不好改"的抱怨 / 文件路径或类名。
- 目标含糊到定位不了代码时反问一次，别猜着往下写。

## 术语（先对齐，方向搞反结论就反）

| | 指什么 |
|---|---|
| **上游** | 被依赖的一方：接口、领域模型、数据模型、公共组件、DB schema、SPI |
| **下游** | 依赖它的一方：调用方业务代码、适配层、Controller、测试 |

判断上下游看**依赖方向**，不看改动成本，也不看谁先写的。

## Phase 1：根因定位

先落到具体代码，再判层：

- 定位涉及的文件 / 类 / 调用链（grep + 读代码，别凭印象）
- 说明这次的问题根因落在**上游**还是**下游**
- ⚠️ 不允许因为"上游改起来麻烦"就把根因判到下游

## Phase 2：上游设计体检 —— 用 5 Why 追到设计决策层

从现象逐层追问，每层写成「因为 X，证据：<文件路径 / 类名 / 接口签名 / 调用链>」：

```
Why1 现象是什么  →  Why2 直接原因  →  Why3 …  →  Why5 设计决策
```

**约束（不满足则本节无效，重做）**：

- 每一层都要挂**代码事实**做证据（文件路径、类名、接口签名、调用链），不允许出现无证据的推测句
- 必须追到**某个可修改的设计决策**为止：谁承担了不该承担的职责 / 哪个边界画错了 / 哪个抽象缺失或多余
- 停在「需求就是这样」「历史遗留」「第三方限制」= **无效根因**，必须继续追问：那为什么当初的设计扛不住这种变化
- 不足 5 层就触底可以，但要说明为什么可以停
- 追满 5 层仍停留在现象层 → 说明 Phase 1 定位方向错了，回 Phase 1 重来

**结论必须二选一明确表态**，不许含糊：

- **上游设计有问题**：指出违反了哪条原则（职责错位 / 接口泄露实现细节 / 贫血模型 / 边界穿透 / 时序耦合 / 抽象层级混乱……）
- **上游设计没问题**：问题出在调用方，说明为什么

## Phase 3：方案

| Phase 2 结论 | 方案要求 |
|---|---|
| 上游有问题 | **主方案必须是改上游**。可附一个"下游兜底"作为备选，但要写清代价 + 偿还条件（什么信号出现时必须回来改上游）；**不允许只给兜底方案** |
| 上游没问题 | 才做下游适配方案 |

## Phase 4：超范围处置

改上游超出本次任务范围时，**不允许自动降级成兜底方案**。要写出：

- 需要改哪里（文件 / 类 / 接口）
- 影响面（谁调用了、要连带改多少处）
- 工作量量级（小时 / 人天级别即可）

然后**停下来让用户决定**，别自己拍板走小路。

## 判方案不合格的信号

出现以下任一项，方案打回重写：

- 为绕开现有坏设计而新增的**适配层 / 转换层 / 兼容分支**
- 为个别场景加的 **if 特判、开关、白名单**
- 「先这样，后面再重构」，却没写清"后面"的触发条件
- 以「**改动小 / 风险低 / 不动现有代码**」作为选择方案的首要理由
- Phase 2 的 Why 链里有任何一层没有代码证据
- Phase 2 结论含糊（既没说上游有问题，也没说没问题）

## 输出模板

```markdown
## 1. 根因定位
涉及代码：<文件/类/调用链>
根因层级：上游 / 下游 —— <一句话理由>

## 2. 上游设计体检（5 Why）
Why1 …（证据：xxx.java:120）
Why2 …（证据：XxxService 接口签名）
Why3 …（证据：调用链 A→B→C）
Why4 …
Why5 → 设计决策：<具体是哪个决策>

**结论**：上游设计有问题 / 没问题
**依据原则**：<职责错位 / 接口泄露实现细节 / …>

## 3. 方案
主方案：<改上游，具体怎么改>
备选（可选）：<下游兜底 + 代价 + 偿还条件>

## 4. 范围与决策点
超范围部分：<改哪里 / 影响面 / 工作量>
需要你拍板：<具体问题>
```
