# cc-code-review

多视角并行代码审查，只出报告、不改业务代码。

## 1. 圈定范围与展开变更清单

1. **复用或圈定范围**：
   - 若上一条助手消息已是 `cc-code-scope` 的 `## 代码范围` 输出 → 直接复用。
   - 否则读取同级 [cc-code-scope/SKILL.md](../cc-code-scope/SKILL.md) 并按其步骤圈定范围；输出 `## 代码范围` 后**不结束本轮**，直接继续本步。
2. **展开为可执行的取数方式与文件清单**（忽略 `.review/`）：
   - 汇总本次范围对应的变更文件及状态（`A` 新增 / `M` 修改 / `D` 删除，含未跟踪文件）。
   - 明确每个子范围的读取方式（如 `git diff`、`git diff --cached`、`git show <sha>` 及未跟踪文件路径），避免各 Subagent 各自猜测或漏掉未跟踪文件。
   - 若变更文件为空，直接告知用户无待审代码并结束。

## 2. 裁剪视角并并行派发只读 Subagent

根据第 1 步的文件清单，**只派发命中触发条件的视角**；未命中的视角由主会话跳过并记录原因，不空跑 Subagent。所有命中的视角使用**只读 Subagent 并行派发**，每个 Subagent 在独立上下文审查并直接返回 Markdown 结论（不写 `.review/` 文件）。

### 传给每个 Subagent 的公共契约

- **输入**：完整传入 `## 代码范围`、变更文件清单（含 `A`/`M`/`D` 状态）及确切的 diff / 文件读取方式。
- **范围边界**：仅报告本次变更引入、放大或直接触及的问题；存量既有问题除非被本次改动恶化，否则不报。
- **证据要求**：每条问题必须给出 `<文件路径>:<行号>`、具体触发路径或规范依据、可执行修改建议；不写无依据的泛泛提醒。
- **严重度定义**：
  - `高`：逻辑 bug、数据损坏/不一致、安全越权/注入、线上故障风险。
  - `中`：违反核心架构/领域/编码规范、边界缺陷、缺失关键业务测试。
  - `低`：局部可维护性或风格改进建议。
- **返回格式**：
  ```markdown
  ## 阶段 X：<title>

  - [高/中/低] `<文件路径>:<行号>`：<问题描述、依据与修改建议>
  ```
  无问题时返回标题 + `- 无发现问题`。

### 审查视角

| 阶段 | title | 触发条件 | 审查任务 |
|---|---|---|---|
| 阶段 1 | 通用逻辑与边界检查 | 总是 | 审查业务逻辑正确性、边界条件、异常处理、并发与资源管理；如涉及多模块改动，核对未破坏既有模块依赖方向。 |
| 阶段 2 | 领域层规范检查 | 涉及后端业务代码新增或结构性调整 | 加载 skill `domain-layer-specification` 审查代码；仅对新增代码（`A`）或新领域模块按新规范严格把关，存量老代码不强求重构。 |
| 阶段 3 | 测试用例检查 | 涉及非纯文案/配置的代码或测试变更 | 加载 skill `testing-guidelines` 与 `cc-testing-boundaries` 审查代码与测试；严格遵守不测边界（不对弱校验、纯类型转换、锁/告警工具调用要求补测）。 |
| 阶段 4 | DB 与迁移脚本检查 | 涉及 `@Entity`、SQL、Liquibase 或 ClickHouse/ByteHouse 变更 | 加载 skill `mysql-guidelines`、`liquibase-guidelines`、`clickhouse-guidelines` 审查表结构、实体映射与迁移脚本。 |
| 阶段 5 | 安全检查 | 涉及接口入口、鉴权、租户/店铺数据读写、外部输入解析或敏感操作 | 审查权限与租户隔离、越权访问、数据伪造、注入攻击与敏感信息泄露。 |
| 阶段 6 | Java 编码规范检查 | 涉及后端 Java/Kotlin 代码变更 | 加载 skill `cc-java-coding-standards` 审查工程取舍、边界校验与反过度判空、Java 17+ 语法（`var`、`switch`、`record`）、禁用 API（`OrikaUtils`、`new Date`）与异常处理纪律；顺带指出明显未使用的类/方法/参数。 |

## 3. 主会话核实、落盘与输出

所有已派发 Subagent 返回后，由主会话完成最终把关：

1. **核实与收敛**：对照源码与调用方核实所有 `[高]` 级和存疑的 `[中]` 级结论，剔除误报与存量无关挑刺，合并跨视角重复项，统一校准严重度。
2. **写入汇总报告**：
   - 确保仓库根目录下存在 `.review/`；若 `.review/.gitignore` 不存在，创建并写入 `*`。
   - 写入 `<仓库根目录>/.review/<YYYYMMDD>-<HHmm>-<短分支名或短hash>.md`（分支名中的 `/` 替换为 `-`），依次包含：
     1. `## 代码范围`（附跳过阶段及原因）
     2. `## 最终 Review 结论`（核实去重后，按 `高 → 中 → 低` 排列）
     3. `## 各阶段原始记录`（完整保留各 Subagent 原始返回，备查）
3. **回复用户**：按 `高 → 中 → 低` 输出核实后的最终 Review 建议，并附上 `.review/*.md` 文件链接。
