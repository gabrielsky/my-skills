# tech-doc-refine

打磨一篇**技术分享文档**——讲清某个外部系统/技术的实际行为，以及我们该怎么用它。
品质单元 = **读者的一个决定**。

默认输出诊断报告，逐条确认后再改。用户说「改」则直接改，并逐条交代内容去向。

## 北极星（唯一判据）

**读者读完这一段，能不能做对一个决定？** 落不到下面任一句，就别记 finding：

1. **会让读者做错决定** —— 断言与一手来源不符；或转述精简过头，从文档自身能推出相反结论（最高价值）；
2. **读者读不懂** —— 给了规则不给它防的问题；用源码的术语而不是读者的语言；
3. **读了等于没读** —— 别处已说过、说了等于没说、或与本文主题无关；
4. **该说的没说** —— 读者读到这里必然会问的问题，文档绕开了。

第 3 类是这份 skill 存在的主要理由：**低价值内容不是中性的，它稀释了真正重要的那几条。**
22 条检查项和 3 条强制项的区别不是"详尽程度"，是"会不会被执行"。

## 与邻居 skill 的分工

| 文档类型 | 用哪个 |
|---|---|
| 规范 / 约定 / 架构设计（指导新代码怎么写） | `cc-tech-spec-review` |
| 产品需求 | `cc-prd-review` |
| 改完 markdown 的文字自查 | `cc-doc-hygiene` |
| 术语单维对齐代码 | `cc-terminology` |
| **技术分享 / 技术介绍（讲清一个已存在系统 + 我们的用法）** | **本 skill** |

和 `cc-tech-spec-review` 最大的差别：**那个 skill 明确不读代码取证，本 skill 必须取证。**
规范文档指导的是未来代码，跟存量比对没意义；技术分享文档描述的是**一个已存在系统的现状行为**，说错了就是错的。

## 三条铁律

### 一、不猜——每条技术断言都要有一手来源

**一手来源优先级**：目标系统源码 > 官方文档 > 博客/记忆。

- 依赖库 → `~/.m2` / `~/.gradle` 里的 `*-sources.jar`，解压读；
- 自部署的开源平台 → 找本地 clone，直接读它的 validator / UI 组件 / 常量表；
- 都没有 → 该断言写成「待核实」并给出核实方法，**不得写成断言**。

三条从实战里来的取证纪律：

- **文档里贴的代码片段不是一手来源。** 转述会丢分支。曾有一段 `isIncludedInRollout` 的精简片段漏掉了 `coverage == 0 → return false`，照它推理得出"关到 0% 仍漏 1‰"，而真实行为是全关——一条会被运维直接采信的错误结论。**凡是从文档自带片段推出的结论，必须回原始源码重推一遍。**
- **注释不是行为。** 曾照一条 `useEffect` 注释推出"新建规则默认 V1"，而真实赋值是 `hasSDKWithNoBucketingV2 ? 1 : 2`（默认 V2）。看赋值和返回，不看注释。
- **自己上一轮的结论也要复查。** 发现推翻时直接说明并撤回，不要为了连贯性硬圆。

### 二、精炼优先于完整

- 每条 finding 必须给**具体动作**：删 / 合并进 X / 压成一句 / 换位置。只说"可以更好"的不算 finding；
- 删除时必须交代**内容去向**：重复了谁、移到了哪、还是真的丢弃。丢弃要说清丢的是什么；
- **判重复看失败模式，不看措辞**：不写这句，读者会做错什么？两处答案相同才是真重复。答案不同就不是重复，哪怕字面像；
- **给方案前先验前提。** 给出 A/B/C 三选一之前问一句"这个前提成立吗"。前提一倒方案全废——曾按"缓存必须留着"给了三套缓存方案，读者反问"那为什么还要缓存"，三套当场塌成一个判据两个出口；
- **先收敛到一个判据，再给出口。** 不要一上来给矩阵。

### 三、不跑题

- 判据：**读者为了完成本文承诺的任务，需不需要这条？** 不需要就是跑题，哪怕它本身完全正确。曾在一份后端文档里展开 CDN 缓存策略，而读者根本管不着 CDN；
- **教科书内容默认删**——通用方法论、别处随手能查到的标准做法，除非它在本文语境下有特殊结论；
- **文档自己声明的边界是硬约束**（如"只针对开源自部署版"）：范围外的能力只在影响工程方案时提一句。

## 常见的低价值形态（照着扫）

1. **摘要块**——开头的"核心原则/要点"逐条对应正文各章，无一条是正文没有的；
2. **目录式清单**——某节的清单逐条对应后面各小节的主题，读完什么也没得到还得往下读；
3. **图 = 文字**——mermaid 图和紧跟其后的文字列表内容相同；
4. **结论句复述**——列了 5 条之后再来一句"因此必须覆盖 A、B、C、D"；
5. **提问不给答案**——"还要考虑：一致性要求、失败行为、权限归属……"；
6. **说了等于没说**——"记录类型和默认值"这类；
7. **规则没有症状**——只给"应该把 X 加进 Y"，不给它防的那个 bug。读者没踩过坑就只会想"为什么"；
8. **位置错**——内容和它所在章节的主题不符。位置错会让读者（和 AI）把这节读窄：一段通用判据挂在某个具体场景的小节下，收口句就会漂成那个场景的专属答案。
9. **调研过程入文**——"已核对源码""行为已核对 X 版源码""经实测确认"这类取证痕迹是写作过程，不是读者要的信息，散在正文里一律删。文档只陈述行为本身；可信度由文档开头的版本边界声明一次性背书，取证记录归 review 报告或 commit message。

## 冗余与引用的裁决规则（找到重复后，照此定留哪处、怎么删）

1. **专题独占**——每个概念指定唯一的"专题节"承载完整论述，其他节的擦边提及一律删，不是压缩。哪节是专题看概念在哪里被推导/定义出来，不看哪里字数多。
2. **各节只说自己那一层**——同一主题允许出现在多节，但分工要硬：对比/介绍节只给**事实**，专题节给**规则**，示例节给**代码**。重复的根源几乎总是某节越界替专题把规则说了，专题只好再说一遍——删越界的那处，不动专题。
3. **结论句可复现，机制解释不可**——一句话结论在别处出现不算重复（"没配 seed 换 key 会重新分桶"）；要删的是跟在结论后面的机制解释。删除时删解释、留结论。
4. **术语即引用**——专题第一次讲透时给概念起名（"静默降级""版本指纹"），后文直接用这个名词：不复述机制，也**不新增"见 X.Y"**。名字本身就是引用——线性读者记得住，跳读者全文搜索这个词就能落到定义处。文档里已有的"见 X.Y"不动，但去重不靠新增它。
5. **先说错再纠正是反模式**——表格或正文先给简化说法，紧跟一段"注意上面其实……"修正。把原处直接写准，修正段整段删掉；读者不该读两遍才知道哪句是准的。

## 工作流

### 0. 建立事实底座（不可跳过）

先找齐一手来源并记下路径，再开始分析。找不到的部分列出来，本轮所有相关断言一律标"待核实"。
底座路径要传给每个 subagent，否则它们会各自猜。

### 1. 通读 + 画骨架

完整读一遍，输出：文档**主题声明**（一句话：本文承诺让读者能做什么）、**章节标题树**、**声明的边界**。
不要边读边写 finding——会漏全局矛盾。

### 2. 切分 + 并行派 subagent（每节一个）

给每个 subagent 的输入**只有**：本节全文 + 章节标题树 + 主题声明 + 边界 + 事实底座路径。
**不要给它整篇正文**——它会跑去评论别的章节，且无法判断跨章重复，两头不讨好。

固定输出 schema，每条 finding 必须齐全：

```
类型:   做错决定 | 读不懂 | 等于没读 | 该说没说
位置:   行号或原文摘录
问题:   一句话
证据:   源码 <文件:行>  |  文档内 <行号>  |  纯推理
动作:   删 | 合并进 X | 压成一句 | 换位置 | 补一句，附改写后文字
```

**证据栏写"纯推理"的，结论一律降级为"待核实"，不得写成断言。**

### 3. 横向检查（单独一个 agent，只做这件事）

**章节级 agent 必然漏跨章问题，这一步是本 skill 的关键，不能省。** 它只看全文，只找五类：

- 同一件事说了几遍、分别在哪、留哪处（按"冗余与引用的裁决规则"定）；
- 前后矛盾（两节对同一行为给了相反描述）；
- 悬空引用（`见 X.Y` 的目标是否存在、是否循环互指）；
- 术语前后是否一致；
- 章节位置是否和所在章主题一致。

### 4. 证伪自检

对每条 finding 逐条问：

1. 证据是哪一行？拿不出行号的降级为"待核实"；
2. 这条是从文档自身的转述推出来的吗？是 → 回一手来源重推；
3. 删除类：把声称重复的两处**原文贴出来对比**，不许凭印象；
4. 这条落在北极星哪一句上？落不到就删掉这条 finding。

### 5. 收敛交付

按"会让读者做错决定 → 读不懂 → 等于没读 → 该说没说"排序。
把判断题（涉及取舍、不是纯废话的）单独列出来交给用户定，不要替他决定。

## 改结构前先算代价

移动章节、改编号之前，**先 grep 谁引用了它，把改动点数出来**。

曾遇到把一个子节提成独立章的选择：插到第 2 章要改 41 处编号引用，放到末尾成为第 7 章只改 3 处，而后者在编排上同样成立（读者读完成本章节再判断边界，判断质量反而更高）。

**最省事的位置常常也是对的位置，但要论证它对，不能只因为它省事。**
