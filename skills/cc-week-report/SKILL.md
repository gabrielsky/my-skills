# 工作简报生成（cc-week-report）

基于指定时间范围内的三路事实证据（本机 AI 会话历史、GitLab 代码提交、GitLab MR 评审），生成可直接用于汇报与留档的三段式工作简报。

## 执行步骤

### 1. 确定时间范围

- 若用户已给出明确日期（如 `2026-11-16 ~ 2026-11-22`）或相对表达（如 `本周`、`上周`、`近7天`、`本月`），结合当前本地日期换算为闭区间 `START` 与 `END`（`YYYY-MM-DD`；其中「上周」指上周一至上周日，「本周」指本周一至今天）。
- 若用户未提供时间范围，先简短向用户确认，给出三个快捷选项（`本周一至今` / `上周一至周日` / `最近 7 天`），确认后再进入采集。

### 2. 运行统一采集脚本

执行本 Skill 目录下的 `scripts/collect.py`（默认 GitLab 组为 `repos/jx/aikf`，主机为 `git.darcytech.com`），将结果写入临时 JSON 文件后再读取，避免终端截断：

```bash
python3 /Users/zhangjianfeng/.ai-tools-hub/repos/custom/skills/cc-week-report/scripts/collect.py \
  --start YYYY-MM-DD \
  --end YYYY-MM-DD \
  --out /tmp/cc-week-report-data.json
```

脚本并发采集以下三路数据（已自动去重子代理会话、排除 Merge 提交、排除自己 MR 下的评论回复）：
- **会话历史**：Antigravity、Claude Code、Codex 三个工具在区间内的用户会话摘要
- **MR Review**：`repos/jx/aikf` 组下你点击过 Approval 的 MR，以及发表过非系统评论但未 Approval 的他人 MR
- **代码提交**：`repos/jx/aikf` 组下全分支去重后的本人非 Merge 提交（已按仓库和关联 Issue 预分组）

检查脚本输出的状态与 `warnings`：若某数据源不可用（如 `glab` 鉴权失效或目录不存在），记录原因，在简报开头如实声明缺失项，继续基于可用数据源生成。

### 3. 清洗证据与交叉归并

读取 `/tmp/cc-week-report-data.json` 后按以下规则提炼：

- **会话过滤**：保留业务研发工作（方案设计、需求分析、代码实现、排障定位、文档与评审等）与有明确产出的研发提效建设（工具链、Skill、工作流等，归入「工程效率」）；忽略纯闲聊、个人生活、一次性简单查询及本次生成简报本身。
- **跨源关联**：按项目/仓库与关联 Issue（如 `proj/jx/aikf#10927`、`maint/jx/aikf#11131`）将同一事项的会话上下文、提交记录和 MR 关联起来，避免重复拆分；无代码提交的纯设计/排障/评审工作同样保留在「核心工作进展」中。
- **编码归并**：在「编码清单」中按仓库分组，把同一 Issue 或同一功能小任务的多次提交合并为一条编码项，保留提交数、最新短 SHA 链接与日期。
- **评审提炼**：在「Review 清单」中保持「已 Approval」与「已评论未 Approval」两个分区；若有 `review_comments`，浓缩为一句话评审关注点（如指出领域服务职责、校验边界等），无评论则写「直接通过」。

### 4. 输出工作简报

直接在对话中输出完整 Markdown 简报，不自动写入项目目录或本地文档（除非用户明确要求保存及路径）。

按以下三段式模板组织，内容严格基于采集到的证据，仅陈述已完成、进行中或待合并的客观事实，不自动编造「下周计划」：

```markdown
# 工作简报（YYYY-MM-DD ~ YYYY-MM-DD）

> 数据范围：会话 N 条（Antigravity x / Claude Code y / Codex z）｜编码提交 M 次（涉及 R 个仓库）｜MR Review P 个（已 Approval A / 已评论未 Approval B）
> （如有数据源异常或缺失，在此单列一行说明）

## 一、核心工作进展

### 业务研发
- **[项目/模块] 事项标题**（`已完成` / `进行中` / `待合并`）
  - 进展要点 1（关联 Issue/MR，简明交代做了什么、解决了什么问题）
  - 进展要点 2

### 工程效率
- **[工具/主题] 事项标题**（`已完成` / `进行中`）
  - 进展要点（如本区间无此类产出可省略本小节）
```

## 完成标准

- 时间范围明确，三个工具的会话与 `repos/jx/aikf` 的提交/评审均已通过脚本采集并核对警告信息。
- 每条编码归并项可追溯到真实 commit SHA，每条 Review 可追溯到真实 MR 链接；无某类数据时写明「本区间无记录」而非留空或杜撰。
- 全文纯事实导向，不包含未经证据支撑的推测或「下周计划」。
